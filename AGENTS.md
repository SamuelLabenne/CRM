# Relay CRM – engineering guide

Relay is a CRM + marketing tool: contacts, campaigns, events with registrations &
attendance, email templates/broadcasts/automations, a calendar, and iClosed-style
booking pages with qualification. Product spec: `docs/SPEC.md`.

## Stack

- **Next.js 16.4** App Router, React 19, TypeScript, Turbopack. `cacheComponents` is **off**
  (classic dynamic rendering). `middleware.ts` is now **`src/proxy.ts`**. `params` and
  `searchParams` are Promises: `export default async function Page({ params }: PageProps<"/events/[id]">) { const { id } = await params; }`.
  Route handlers: `export async function GET(req: NextRequest, ctx: RouteContext<"/api/x/[id]">)`.
  `PageProps`/`LayoutProps`/`RouteContext` are global types generated by `next typegen`.
- **Tailwind v4 + shadcn/ui (radix-nova)** in `src/components/ui` (don't edit these unless necessary).
  Icons: `lucide-react`. Toasts: `import { toast } from "sonner"`. `cn` from `@/lib/utils`.
- **Drizzle ORM + Postgres.** Local dev uses an embedded Postgres (PGlite) at `.data/pglite`
  (migrations run automatically on dev-server start). Production uses `DATABASE_URL` (Supabase).
- **zod v4** for validation, **date-fns v4** + `@date-fns/tz`, **FullCalendar** (calendar),
  **TipTap v3** (email editor), **recharts** via shadcn `chart`, **@dnd-kit** (drag & drop), **papaparse** (CSV).

## Commands

- `npm run dev` – dev server (port 3000). Only one dev server per checkout.
- `npm run typecheck` – `next typegen && tsc --noEmit`. **Run before you finish.**
- `npm run lint` – eslint. `npm test` – vitest (unit tests in `src/**/*.test.ts`).
- `npm run db:generate` – generate a SQL migration from `src/lib/db/schema.ts` into `./drizzle`.

## Architecture & conventions

- `src/app/(auth)` – login, first-run setup, invite acceptance.
- `src/app/(app)` – authenticated app (sidebar shell in `layout.tsx`). One folder per module.
- Public pages (no auth): `/e/[slug]` event registration, `/book/[slug]` booking page,
  `/m/[token]` attendee self-service (RSVP/cancel/calendar), `/u/[token]` email preferences,
  `/embed/*` embeddable variants. Public prefixes are whitelisted in `src/proxy.ts`.
- `src/lib/*` – server-side domain logic shared by modules (see below). Prefer putting logic in
  `src/lib/<module>/…` and keeping pages thin.
- **Server Components fetch data directly with Drizzle.** Mutations are **Server Actions** in a
  colocated `actions.ts` (`"use server"`). Every action and every protected page/route handler
  must call `await requireUser()` (or `requireAdmin()`) from `@/lib/auth` – server actions are public endpoints.
- Actions return `ActionResult` (`ok(...)` / `fail(...)` / `zodFail(...)` from `@/lib/action`) and
  call `revalidatePath(...)` after mutating. Client components use `useActionState` or
  `useTransition` + `toast.success/error`.
- Use `PageHeader` + `PageBody` (`@/components/app/page-header`) for every app page, `EmptyState`
  for empty lists, `StatusBadge`/`MappedStatus` + the shared status maps in
  `@/components/app/status-badge` for statuses, `StatCard` for KPIs, `UserAvatar`, `ContactPicker`,
  `ConfirmDialog`, `SubmitButton`. Dates: `formatDateTime/formatDate/timeAgo` from `@/lib/format`
  using the workspace timezone (`(await getSetting("workspace")).timezone`).
- Keep pages responsive (they must work at 375px width) and support dark mode (use theme tokens like
  `bg-card`, `text-muted-foreground`, never hard-coded grays for surfaces).
- Long lists: server-side pagination with `?page=` (25–50 per page) and filters in the URL (`?q=`, `?status=`).

Background work goes through the `jobs` table: register handlers in your module's
`*JobHandlers` map (see `src/lib/jobs/handlers.ts`). Jobs run every minute via `/api/cron`
(production), on a 20s timer in local dev, and right after requests that call `kickJobs()`.

## Database changes

`src/lib/db/schema.ts` is shared. Avoid schema changes; if you truly need one, make the minimal
additive change (new nullable column / new table), run `npm run db:generate` to test locally,
but **do not commit files in `./drizzle/`** (`git checkout -- drizzle && git clean -fd drizzle`)
– the integrator regenerates migrations. Mention schema changes in your final report.
